# 実画面の手動テスト

画面収録とアクセシビリティの許可を持つMacで確認します。自動テストだけでは、OSの権限や実アプリの操作は検証できません。

`demo.html`をブラウザで開きます。4ページの合成資料で、ページ送りボタンは固定位置です。最終ページでは進まないため、末尾での停止判定も確認できます。

## 確認項目

- [ ] 初回起動時に意図しない撮影やクリックが発生しない。
- [ ] 権限がないとき、実行を止めて必要な設定を表示する。
- [ ] 範囲選択とボタン位置選択をEscでキャンセルできる。
- [ ] ボタン位置の選択中に資料のページが変わらない。
- [ ] テスト撮影でページ全体が入り、ブラウザのタブや操作ボタンが含まれない。
- [ ] 1ページ指定では自動クリックせず、1ページだけ保存する。
- [ ] 3ページ指定でPDFとPNGが1、2、3の順に保存され、最終撮影後に余分なクリックがない。
- [ ] 6ページ指定では資料の4ページ目の後に停止し、4ページのPDFを残す。
- [ ] 重複検出をオフにすると、最終ページを繰り返し撮影して指定枚数まで保存する。
- [ ] 撮影開始前のカウントダウン中に停止すると、PDFを作らない。
- [ ] 途中停止で撮影済みページがPDFに残る。
- [ ] Escとメニューバーから停止できる。
- [ ] 別アプリを前面にすると停止し、そのアプリへクリックを送らない。
- [ ] PDFがプレビューで開き、A4横とA4縦で印刷範囲に収まる。
- [ ] マルチディスプレイで各画面の範囲を正しく選択できる。
- [ ] 許可の取り消しや対象アプリ終了時に停止し、保存済みのPNGを失わない。

## 記録

macOS、CPU、ディスプレイ構成、アプリのバージョン、確認した項目を記録してください。未確認の項目は未確認のままにします。

初期alpha版では、このチェックリストは未実施です。自動テストの対象と実行手順は[README](../README.md)に、実行結果は[GitHub Actions](https://github.com/fuminaka1014/pagecapture/actions)に記載しています。
